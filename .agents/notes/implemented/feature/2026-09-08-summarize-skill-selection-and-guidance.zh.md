# Agent Note：/summarize-skill 接收选择与指引，不再靠猜

Status: implemented

[English](2026-09-08-summarize-skill-selection-and-guidance.md) | 中文

## Problem

`/summarize-skill` 把整段对话和一条通用规则交给子代理，由子代理猜测什么值得保存。明明知道哪几轮教了工作流、skill 该强调什么的用户，却没有渠道表达。

## Decision

命令现在把输入解析为"可选选择器 + 自由文本指引"。开头的 `N` 表示只取最近 N 轮；开头的 `N-M` 表示按 1 起始的闭区间选择完整对话；其余文本（或没有选择器时的全部输入）作为指引，有指引时子代理优先遵循指引而非通用的"自行判断"规则。配置的 `maxTurns` 仍对最终选择封顶，部署可以不依赖输入地限制委托成本。

## Alternatives considered

- **结构化子命令或旗标。** 暂缓：单条斜杠命令加前缀选择器，能在任何命令界面直接使用，无需每个界面单独适配。
- **消息选择器 UI。** 暂缓：客户端尚无按命令自定义输入的界面；选择器语法就是未来选择器 UI 要喂给命令的契约。

## Consequences

- 无效选择器在任何子代理启动之前显式报错，并给出越界的数字。
- 指引在子代理提示词中面向模型，但不触碰主对话前缀，也不进会话日志。

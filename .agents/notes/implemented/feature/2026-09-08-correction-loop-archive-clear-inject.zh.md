# Agent Note：纠错闭环 = 融合、归档、清空、注入

Status: implemented

[English](2026-09-08-correction-loop-archive-clear-inject.md) | 中文

## Problem

第一版 `/correct-errors` 只根据日志写一份新反思，日志却永远增长：前几轮的经验到不了下一轮，每次纠错都要重读所有旧失败，而产出文档按项目存放，其他会话看不到。

## Decision

纠错闭环现在有四步。融合：命令读取日志与既有系统级反思文档的截尾，一并交给子代理，由它重写完整文档并新增一个日期分节。归档：日志原始内容追加进 `<dshHome>/tool-error-log-archive.jsonl` 这个只追加写的账本。清空：日志截断为空，为下一轮定界。注入：新的 `error-reflection-prompt` 插件把文档截尾作为 `deployment:error-lessons` 系统提示词分节注入，让每个 agent 携带最新经验。文档与插件默认指向同一个 Harness home 路径；归档与清空只在子代理启动成功后执行，启动失败永不丢日志数据。

## Alternatives considered

- **让子代理归档并清空日志。** 否决：文件簿记是确定性工作；把输入日志的写权限交给子代理，等于让一次模型失误有能力销毁证据。
- **在命令里用字符串拼接合并反思。** 否决：综合是模型工作；拼接只会让日期分节越堆越多，而不是去重浓缩。
- **注入整份文档。** 否决：文档无界增长；带标题边界的有上限截尾既给提示词成本封顶，又由归档保全全部内容。

## Consequences

- 每轮纠错从空日志开始；归档是每条原始失败的永久记录。
- 经验是部署级全局的（Harness home），与全局日志的作用域一致。
- 文档变化时注入分节会使请求前缀移位——对低频、用户手动触发的纠错而言可以接受。

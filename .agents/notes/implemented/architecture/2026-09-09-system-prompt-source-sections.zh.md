# Agent Note: 保留系统提示词来源分段

Status: implemented

[English](2026-09-09-system-prompt-source-sections.md) | 中文

## 问题

客户端能看到"模型收到了什么"，却看不到"它来自哪里"：提示词是一整块渲染结果，因此当提示词发生变化时，只能把整块再展示一遍。让客户端自己切分只是猜测——只有装配阶段知道哪段文本由哪个提供方、以什么顺序、插值之后贡献。

## 决定

请求头记录一个可选的 `systemSections` 列表：装配提示词所用的已插值来源，供客户端按来源展示。渲染后的提示词正文本身不进请求头——它是派生历史，即 surface 节点 0 的 `system/message` 事件——而提示词变更以新的请求系列到达模型，因此 `systemSections` 是"会被记录与折叠、但不参与请求头比较"的展示元数据。没有该字段的旧请求头保持有效，并回退为一个旧版整段。

## 备选方案

**继续在请求头里保存整段提示词，由客户端做文本 diff。** 否决：文本 diff 把变化归到"行"，而不是归到拥有这些文本的提供方；而且一旦把提示词正文放回请求头，它就会重新进入"请求头是否变化"的相等判定。

**每个分段记一条会话事件。** 否决：为"只有打开提示词才读"的数据，每请求记几十条小事件，且每条都要在 surface 模型里占一个位置。

**由客户端按分段契约自行重建分段。** 否决：客户端 bundle 无法值引用另一个插件的装配结果，只能重新实现插值与提供方排序——等于给"模型看到了什么"再造一个真相来源。

## 后果

客户端可以按来源分组展示提示词，并在报告变更时只显示发生变化的分段；没有该字段的旧请求头回退为完整提示词而非空。该字段的代价是每请求在日志里多一个数组，且绝不能再参与请求头相等判定——提示词变更已由请求系列表达。

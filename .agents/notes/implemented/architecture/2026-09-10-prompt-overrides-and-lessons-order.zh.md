# Agent Note: 提示词覆盖与错误反思顺序

Status: implemented

[English](2026-09-10-prompt-overrides-and-lessons-order.md) | 中文

## Problem

错误反思此前注入在工具引导之前，实时纠正可能被静态工具说明埋住、读起来像过期建议。`/correct-errors` 提示词要求写很长的反思，把它自己所在的分段挤满。部署方若不修改注册该文本的包，就无法改动第一方提示词。

## Decision

`deployment:error-lessons` 使用专用工具段之后的段位，因此实时错误反思会跟随所有工具介绍之后注入。`/correct-errors` 子代理提示词改为简短中文，并要求只新增一个日期小节、最多五条要点。

可选的 `system-prompt-overrides` 设置段允许 Web 原位替换第一方提示词段，中文和英文分开存储。用户编写的 `mcp:intro` 段也可编辑。由于提示词注册表在每次组装时读取覆盖内容，修改会影响已有会话的下一次请求。

## Verification

系统提示词、设置插件、纠错命令和错误反思测试通过。重建 Web 后的新会话可以看到新的“系统提示词”卡片、中文运行时上下文开头，以及位于工具引导之后的错误反思段。

## Alternatives considered

**在反思文本内部用行文顺序表达先后。** 否决：真正起作用的是"分段之间"的顺序，而那只受分段顺序分配表控制。

**用估算的 token 预算来限制反思长度。** 否决：条数是提示词和读者都能核对的；预算依赖一个写反思的模型看不到的估算值。

**通过部署 patch 文件覆盖提示词提供方。** 否决：patch 文件表达的是接线而不是文案——写在那里的文案对设置卡片不可见，且会在下一次上游变更中丢失。

## Consequences

实时纠正会出现在它所纠正的引导之后，反思段也短到可读。由于注册表在每次组装时读取覆盖内容，一次编辑会影响运行中会话的下一次请求：不需要重启，客户端也不再持有文本的第二份拷贝。

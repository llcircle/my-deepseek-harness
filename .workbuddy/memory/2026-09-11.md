**缺陷一：`computer_drag` 从上线起就没成功过。** TS 侧发 `fromX/fromY`，脚本侧 `action_drag` 复用只认 `x`/`y` 的 `optional_point()`，起点恒为 `None`，必报「drag 需要 fromX/fromY 作为起点」。真机连续 3 次全失败，模型只好改用 click + shift+down + shift+end 绕过。修法：抽出 `optional_point_named(request, x_field, y_field)`。

**缺陷二：`computer_scroll` 方向与对外契约相反。** schema 写「deltaY 为正向下滚」（对齐 DOM WheelEvent），但 Win32 `MOUSEEVENTF_WHEEL` 正 `mouseData` 是向上滚。上一轮没暴露，是因为打开的文档不足一屏——"无变化"被误当成"正常"。修法：边界处纵向取反，横向 `MOUSEEVENTF_HWHEEL` 不取反。

**教训（写进 EXPERIENCE.md 了）：mock 掉 provider 方法的测试证明不了 Python 脚本是对的。** provider 与脚本之间那一行 JSON 的字段名和符号约定，必须真喂一次脚本才算验过。新增 3 例 `runtime.spec.ts` 全部绕过 provider 直接调脚本，用空实现替掉鼠标输入后校验返回值/事件负载。

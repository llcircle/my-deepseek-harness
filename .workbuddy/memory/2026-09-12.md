## 踩坑（重要，复用价值高）

- **tsx + tsconfig paths 只映射主入口**：`@deepseek-ai/dsh-system-prompt` 走 `src`（新代码），但子路径 `@deepseek-ai/dsh-system-prompt/overrides` 走 package exports → `lib/overrides.js`（旧构建）。改完源码必须重建对应包的 lib（`node node_modules/tsdown/dist/run.mjs --env.DSH_BUILD_FACE host --filter <pkg>`），否则真机行为与单测不一致。pnpm shim 在本机已损坏（Git Bash 调用报 loader 错），用受管 node 直接跑 tsdown/run.mjs。
- **生成目录必须随新事件/新工具重新生成**：加 `computer/mode` 事件后没跑 `gen-persistence-catalog`，导致重启后含该事件的会话拒绝恢复（"unknown event type ... refusing to interpret the log"）。同理 `gen-tool-catalog` 的 TOOL_PACKAGES 漏登记新工具包会让 gen 测试失败（新类别 `onDemandTools` 解决按需/无工具包的登记）。
- **pnpm shim 损坏的绕行**：workspace 链接可直接用 PowerShell `New-Item -ItemType Junction` 手工建（pnpm 的链接产物就是它）。
- **本机 Bash 工具对长命令易 SIGTERM**：robocopy 全量备份、部分 curl+管道组合都被杀过；curl 输出必须 `-o 文件` 再 cat，不要接 head 管道（exit 23 会吞结果）。
